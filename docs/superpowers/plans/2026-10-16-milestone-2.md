# Concurrent Broadcasting, Audio, and Fullscreen Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let multiple people broadcast and watch independent streams in the same room, with working opt-in audio and fullscreen bars that hide automatically.

**Architecture:** Extend the existing session/stream model and retain one shared H.264/Opus pipeline per broadcaster. Add explicit audio selections, a guarded WASAPI endpoint adapter, and coordination between capture and in-app playback. Implement fullscreen visibility independently of the WHEP lifecycle.

**Tech Stack:** Windows 11, C#/.NET 10, WPF/WebView2, C++20/OBS 32.2.2, MediaMTX 1.21.2, React/TypeScript, xUnit, native CTest, Vitest, Playwright.

**Spec:** [Approved M2 design](../specs/2026-10-16-milestone-2-design.md), approved by the user on 2026-10-16. Baseline product commit: `1ec3c3d`; implementation starts from `81d4794` on `codex/m2-design`. The user approved execution on 2026-10-16 and selected subagent-driven implementation. Every implementer/reviewer uses GPT-6.1 Sol with explicit reasoning effort.

## Global Constraints

- “Remove the fixed per-room participant and publisher limits.” Preserve one publication per session; do not introduce a different room people/stream quota.
- “Do not introduce a replacement reader cap or bandwidth-admission policy.” Keep existing bounded queues, timeouts and unrelated infrastructure safeguards.
- “There is no required one/four/eight-viewer capacity benchmark, large-group test, or external eight-viewer sign-off.” Functional concurrency and working audio still require honest evidence.
- “Keep one shared H.264/Opus encoding pipeline per broadcaster, independent of that stream's viewer count.” Preserve NVENC, explicit capped CPU fallback, repeated headers, ownership, leases and controller/source lifetime checks.
- Audio modes are `Off`, `Application(process identity)`, and `SystemOutput(render endpoint ID)`. “Selecting a display never silently enables system capture.” No microphone or automatic audio-mode fallback.
- Preserve the 200 ms drop-oldest PCM queue. System output is explicit monitor-sharing audio; its fixed render endpoint can include Discord and incoming playback.
- Fullscreen entry hides both overlays/cursor immediately; movement reveals them; inactivity timeout is two seconds. Keyboard/touch access and continuous playback remain available.
- Use existing pinned dependencies. Reuse the project directory; keep generated binaries, runtime state, credentials and raw artifacts out of Git. Use the configured repository-local author.
- Every delegated implementer/reviewer uses `gpt-6.1-sol` with explicit reasoning effort; never `gpt-6-astra`. Recommend native execution here because the audio tasks share contracts and cleanup state; keep a fresh final reviewer on GPT-6.1 Sol high reasoning.

## Review Focus

1. Two publishers have the same nickname, and one disconnects: the other's publication/readers must survive. Pin in Task 1.
2. Fullscreen was entered by a focused pointer button: that stale focus must not keep the bars visible. Pin in Task 3.
3. Default audio device changes during capture or a settings restart: keep the selected endpoint, never follow the new default. Pin in Tasks 4, 6 and 7.
4. Stop/fault/cancellation races audio preparation: no new capture may emit after release, and in-app sound cannot resume before the owned helper has stopped. Pin in Tasks 6–8.
5. Quiet media or incomplete diagnostics: silence is not failed initialization; unavailable data must not become a fabricated zero or passed audibility result. Pin in Tasks 2, 6, 7 and 9.

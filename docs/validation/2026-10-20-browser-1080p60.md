# Browser broadcasting at 1080p60

2026-10-20, branch `codex/browser-broadcast-1080p60`, based on `main` at `7e43d5f`. This report accompanies the browser quality change; earlier M3 reports keep their recorded revisions, workloads and acceptance limits.

## Behavior

The browser now requests 1920x1080 at 60 fps using `ideal` and `max` capture constraints, both in the user-initiated chooser request and on the selected video track. No minimum/exact source requirement is imposed. The single H.264 video sender has a 12,000,000 bit/s and 60 fps ceiling, set at transceiver creation and reapplied after negotiation. Smaller/slower sources remain usable. Audio stays opt-in, with no microphone capture. Ownership, cleanup and the single shared feed remain intact.

These are targets and ceilings, not guaranteed output or a constant bitrate. Source, browser, encoder and network adaptation determine the actual stream. Browser encoder selection remains separate from native AMF/NVENC controls.

Firefox follow-up: the owner's real screen test exposed a separate H.264 Level 3.1 negotiation limit after this initial change. The [Firefox correction and measurements](2026-10-20-firefox-1080p60.md) record the host-side fix and short real Firefox/MediaMTX encode/decode evidence. The original verification below remains evidence for its recorded revision and Edge workload.

## Verification

- Baseline: all 98 existing browser tests passed. Test-first regressions then failed against the old capture/sender limits and passed after the change; the focused publisher/WHIP suite passed 37 tests.
- `./scripts/Verify.ps1 -Mode CodeOnly`: passed **292 managed tests, 99 browser tests and 43 native checks**, production/app/probe builds and setup/headless checks. An initial sandboxed run stopped in Visual Studio FileTracker with `E_ACCESSDENIED`; the complete rerun outside the sandbox passed. The native plugin was compiled, not installed.
- `./scripts/Test-BrowserPublishing.ps1`: passed **4 real local browser protocol cases** on the final branch, using Edge **155.0.4283.62**, pinned MediaMTX **1.21.2**, one publisher and one viewer in separate browser contexts on the same Windows PC with loopback signaling/media. Cases cover 640x360 video-only, requested-but-unavailable audio, captured Opus audio, and 1920x1080/60 video. They verify H.264 decode, successful WHEP negotiation, available Opus audio energy and Stop sharing cleanup.
- The 1080p60 case uses a synthetic moving bar, a five-second startup warmup and a **5.0013-second** decode sample: **59.9844 decoded fps**, ending at **1920x1080**. The source reported 1920x1080/60; the real sender reported one encoding with `maxBitrate=12000000`, `maxFramerate=60`, `scaleResolutionDownBy=1` and no quality limitation at sampling. Its target bitrate at sampling was 5.485 Mbps, not a measured constant 12 Mbps output. A preceding run of the same moving-bar fixture also passed at approximately 59.99 decoded fps.
- Exploratory whole-frame color-change fixtures initially measured approximately 54.99 decoded fps or adapted to 720p/60 with a browser-reported bandwidth limitation. The moving-bar result does not establish high-motion or arbitrary-workload 1080p60 performance.
- Independent read-only GPT-6.1 Sol review of the implementation and final protocol fixture found no actionable issues. `git diff --check` passed.

Raw logs stay ignored under `.artifacts/browser-1080p60-*`; invitations, credentials and raw test artifacts are excluded from Git.

## Limits

The protocol fixture substitutes only synthetic canvas/tone tracks for the display chooser. The production controller, authentication, publication/leases, WHIP/WHEP, actual browser encoding/decoding and MediaMTX remain real. This short local check does not establish actual screen/window/tab capture behavior, human-audible captured audio, sustained presentation smoothness, external-network stability, other browser/device compatibility, hardware encoder identity, native/browser coexistence or CPU/GPU/game impact. No release package was produced, and the remaining M3 live acceptance gates are unchanged.

# Room diagnostic reports

Open **Playback diagnostics** beneath a viewer, or read **Observed** in the Windows app. Export with either room export button. The PowerShell alternative is `./scripts/Export-Diagnostics.ps1` after joining through the native app; it reads the current user's encrypted session, never prints the credential, and writes redacted JSON.

Reports hold at most two minutes / 4096 observations globally. Authenticated room members can export their room's active streams. Publisher reports require stream ownership. The server assigns an opaque observer UUID so multiple viewers' observations can be separated; UUIDs are identifiers, not login credentials. Nicknames, executable paths, invitations, bearer credentials, ICE addresses, and arbitrary strings are excluded by a field/value allowlist. Do not export OBS logs or raw RTC stats as a substitute: those can contain private data.

Browser samples run once per second, with bounded five-second rolling history. Received video Mbps is byte delta × 8 / seconds / 1,000,000; audio/network overhead is additional. Decoded FPS is the `framesDecoded` delta. Presented FPS uses `requestVideoFrameCallback`'s `presentedFrames`, meaning submitted for composition, not physical scanout. Unsupported or reset counters remain null. Background/paused playback is excluded from presentation/stall tracking. A selected ICE candidate pair is required to classify direct/relayed; nominated candidates alone do not prove the connection path. ICE RTT is network round trip, not video latency.

Publisher counter rates use the native monotonic clock; requested and applied settings are targets, distinct from observed output. Native encode API time and fresh capture-to-output timing have the limitations described in [diagnostic coverage](diagnostic-coverage.md). Browser and native clocks are not subtracted from one another.

Host `mediaBytesSent/Received` sum MediaMTX 1.21.2 `outboundBytes/inboundBytes` for currently live WebRTC sessions in the room. Three-second cached interval Mbps matches session UUIDs and becomes unavailable for newly seen/reset counters. These totals can fall when sessions leave; they are not lifetime totals. `estimatedViewerMbps` uses applied publisher bitrate targets × active media readers (one stream in milestone one); it excludes overhead and differs from measured media traffic. NIC byte totals include all active non-loopback interfaces, other applications and possibly overlapping VPN traffic; they cannot be attributed to JKiller. Local loopback media does not measure internet upload.

Actual native-to-Edge short synthetic tests passed 720p30 and 1080p60 with H.264/Opus, fullscreen return, numerical nonblank pixels, positive presented/decoded and native encoded rates, and at least two live host media sessions. Redacted numeric reports are in `.artifacts/diagnostics/live-room-{720,1080}.json`. The fixture produces approximately 40 changing frames/s even when encoding/presentation are near 60; these smoke tests do not establish smooth 60 FPS gameplay, audio exclusion, eight-viewer capacity, external reachability, or end-to-end latency.

Field definitions verified against [W3C WebRTC statistics](https://www.w3.org/TR/webrtc-stats/), [video frame callbacks](https://wicg.github.io/video-rvfc/), and [MediaMTX 1.21.2 API schema](https://github.com/bluenviron/mediamtx/blob/v1.21.2/api/openapi.yaml).

# Portable build and room-presence changes

The user requested a Windows ZIP for friends, departed-user cleanup, and restoration of the previous application-audio option. The user explicitly accepted experimental app-and-child-process capture and asked to skip live tests. No apps, browsers, media servers, capture fixtures or audio tones were launched for this work. An existing host was left running; isolated output paths avoided its locked DLL.

## Delivered behavior

- The portable Windows x64 broadcaster bundles .NET and a clean, hash-verified OBS runtime. Extract the whole ZIP and open `PlayKross.exe`. The room host runs separately; browser-only viewers need no ZIP. WebView2 Evergreen and Visual C++ x64 runtime remain possible prerequisites, documented in the included README.
- Explicit **Leave room** releases membership, owned streams and media permissions immediately. Closing the native app also attempts Leave. Browser disconnection gets a 30-second reconnect grace after the server detects the final socket ending; silent network loss also incurs transport detection time. Another active tab retains the shared membership. Idle native apps renew presence every five seconds. Passive expiration permits invitation/capacity checked readmission using the same unexpired identity.
- Audio is off by default and explicitly experimental. Steam Geometry Dash is the supported user application; the development fixture is also permitted by policy. Direct Discord, browser, system-output, microphone and room-playback capture remain unavailable. The native layer independently checks the supported profile, exact process identity/lifetime and owner ancestry. Windows includes future child processes: this does not guarantee Discord exclusion and does not meet the original strict requirement. No live sound or exclusion result is claimed.

Presence regressions were observed failing before their fixes. Independent scoped review found failed-rejoin heartbeat cancellation and expiry-related cleanup failures; each received a regression and was corrected, with final focused review clear. The audio restoration expectation failed against the disabled mode before restoration; tests now verify explicit supported-process selection and deny direct engine/native policy bypass. They do not establish audio isolation from future children.

Packaging initially stopped safely on known WebView2 documentation files and on ZIP timestamp ordering; exact documentation exclusions and timestamp-before-write corrected those issues. Failed attempts produced no release ZIP. A final check found that adding runtime-specific entries to regular dependency locks broke nonportable locked restore (NU1004). Portable builds now use separate `packages.portable.lock.json` files with locked restore, preserving the normal locks. App-only conditional naming preserves development assembly paths.
